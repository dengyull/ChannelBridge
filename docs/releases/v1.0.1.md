# ChannelBridge v1.0.1

## 中文

本次更新主要改善后台性能，并增加低延迟和高级缓冲设置。

### 后台性能优化

- 服务和界面的定时格式检查只查询当前音源，不再扫描全部播放设备。
- 及时释放设备查询、输出初始化和测试播放创建的临时 AudioClient。
- 保留原有声道映射、音量跟随、时钟漂移校正及设备恢复机制。
- 一台 32 逻辑处理器电脑的短时采样中，整机 CPU 占用从约 1.39% 降至 0.015%–0.048%；结果仅作参考，不代表所有设备或低延迟设置下的占用。

### 低延迟与高级设置

- 新增低延迟档：**捕获 25ms / 转发输入 50ms / 输出设备 20ms**。
- 右上角新增 **高级设置 → 音频缓冲**，三个数值可独立输入，平时隐藏在弹窗内。
- 捕获及输出可设为 10–500ms，转发输入可设为 10–1000ms；可一键恢复低延迟默认值。
- 配置保存、载入、服务重启及麦克风测量使用相同缓冲设置。
- 兼容旧配置；标准档保持 100/80/40ms。早期本地 40ms 预设迁移到 50ms，显式自定义值保持不变。
- 增加配置兼容、缓冲范围、时钟漂移与输入抖动测试；支持中英文和高 DPI。

### 升级与使用

下载 `ChannelBridge-v1.0.1-win-x64.zip`，解压并运行新版程序，点击启动或应用配置，按需批准服务升级的管理员提示。勾选低延迟，或在高级设置中编辑后点击“应用配置”。旧本地自定义配置如需使用本次默认值，请先点击“恢复 50ms 默认值”。

缓冲数值是请求值/队列目标，**不是端到端延迟保证**；设备驱动可能调整实际大小，音箱补偿还会增加延迟。不修改 VB-CABLE 控制面板的内部缓冲。出现爆音时可增加缓冲或切回标准档，切换后建议重新测量补偿。最终默认档的爆音改善仍需实际播放验证。

发行包由 GitHub Actions 编译、检查并打包，附 SHA256 校验文件；不包含虚拟音频驱动。

## English

This update reduces background overhead and adds configurable low-latency buffering.

- Periodic service/UI format checks query only the selected source instead of enumerating every playback device. Temporary audio clients are disposed promptly.
- Low-latency preset: **25ms capture / 50ms routing input / 20ms output**; standard mode remains 100/80/40ms.
- **Advanced → Audio buffers** at the top right exposes three independent inputs. Capture/output support 10–500ms; routing supports 10–1000ms. Reset restores the low-latency defaults.
- Buffer settings persist in profiles, survive service restarts and are used by microphone calibration. Older public profiles retain standard mode; explicit custom values are preserved.
- Added configuration, clock-drift and capture-jitter checks, plus bilingual high-DPI UI support for the new controls.

Extract the ZIP, launch the new executable, then start/apply to upgrade the service with administrator approval when requested. For older local custom profiles, use Reset to 50ms defaults to adopt 25/50/20ms.

These are buffer requests/queue targets, not guaranteed end-to-end latency. Drivers may round actual buffers; speaker compensation adds delay. Smaller values can cause crackling. Increase buffering or return to standard mode if necessary. Acoustic performance of the final preset still requires listening tests. VB-CABLE internal buffer settings are unchanged.

GitHub Actions builds, checks and packages the Windows x64 release. SHA256 checksums are included; virtual audio drivers are not bundled.
