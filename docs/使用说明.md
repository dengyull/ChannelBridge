# ChannelBridge 1.0：Windows 多设备环绕声路由

双击 `app/ChannelBridge.exe`。Windows x64，自带运行时。

最小化按钮左侧的“文 / A”图标可即时切换中文和英语，记住上次选择。切换不影响当前预设和后台播放。语言设置位于 `%LocalAppData%\ChannelBridge\language.txt`，设备名称保留 Windows 原名。英文界面的 Help 打开英文使用说明。

首次启动默认选择 CABLE Input；没有找到时会弹窗提示，并打开 https://vb-audio.com/Cable/ 官方下载页面。安装驱动后按提示重启并刷新设备。已有保存配置优先恢复原音源，不覆盖用户选择。右上角“系统声音设置”打开 Windows 声音控制面板。

界面采用浅色分区、圆角按钮、悬停反馈及统一的列表配色，保留键盘焦点、高 DPI 缩放和小窗口滚动。

## 一次应用，完成 Windows 设置与路由

1. 选择虚拟播放音源，例如 CABLE Input，并选择目标声道布局。
2. 点击音箱，在右侧分配输出设备、L/R、增益、延迟和静音。
3. 点击“应用配置”，或“启动服务 / 路由”。程序会同步所选音源的 Windows 声道模式，读取实际格式，匹配声道，再保存路由。
4. 首次安装服务或修改 Windows 扬声器属性需要时会请求管理员提权。若模式未变且权限足够，不会多弹授权。

不需要另外打开 Windows 扬声器配置向导。修改的是所选播放音源，不修改其他物理输出设备或系统默认设备。切换模式会短暂中断音频；某些播放器可能需要重新开始播放。已经打开的 Windows 声音窗口可能缓存旧设置，请关闭再打开查看。

配置会先校验输出设备和映射，再设置 Windows。设置后校验声道数、声道位置掩码和 Windows 扬声器配置；不支持、权限不足或读回不一致会报错。失败时尝试恢复原 Windows 设置，不保存新的路由；若恢复也失败，会报告恢复错误。

“应用配置”保留之前的运行/停止意图；“启动服务 / 路由”保存为开启。改变下拉布局本身只是编辑草稿，点击应用才修改系统。

## 自动匹配与布局

支持 2.0、2.1、3.0、3.1、4.0、4.1、5.0、5.1 侧环绕、5.1 后环绕、6.0、6.1、7.0、7.1，共 13 种布局。

默认“自动匹配：开”。音源声道依据实际 Windows 扬声器位置匹配；后端持续检测格式变化并重新连接。四声道源的后环绕是第 3/4 声道，5.1 后环绕源是第 5/6 声道。物理设备、L/R、增益和延迟保留。自动模式下隐藏音源声道设置，关闭自动匹配后恢复显示；关闭自动匹配可手动指定索引，应用时仍将 Windows 音源模式设为所选布局。

不合成缺失声道，不做立体声上混、低通分频或 Dolby/DTS 解码。LFE 仅转发已有低音信号。每侧独立增益 -60～+6 dB，延迟 0～500 ms。各设备有缓冲与漂移补偿，不能代替硬件时钟同步。

## 系统音量与测试

下方“系统音量：跟随”默认开启，后台输出和测试音跟随所选音源（如 CABLE Input）的 Windows 音量与静音。切换后点击应用；不会修改物理设备自身的音量。若任务栏选中别的设备，滑块控制的也是别的设备。

若驱动已经对捕获音频应用了系统音量，可切换为“系统音量：直通”并应用，避免重复衰减。[VB-CABLE 官方手册](https://vb-audio.com/Cable/VBCABLE_ReferenceManual.pdf)第 13 页介绍了驱动的 Enable Windows Volume Control 选项；本工具不修改该驱动选项。

右侧“播放测试音频”测试选中音箱，下方“测试配置”按布局顺序逐个播放已连接且非静音的音箱。普通音箱 440 Hz，LFE 60 Hz，每次约 0.8 秒，加上配置延迟及间隔。测试使用当前预设的物理设备、接口、增益与延迟；不验证播放器到虚拟音源的上游信号。

测试期间暂停路由，可点“停止测试”；结束后恢复此前状态。关闭 UI 后已开始的测试序列会完成；服务重启不重播旧测试。

## 麦克风自动延迟补偿

下方点击“麦克风测延迟”，在弹窗中选择麦克风。固定麦克风在听音位置，暂停其他播放，关闭麦克风监听，保持输入/输出音量不变，再点击“应用并开始测量”。此按钮先应用当前预设和 Windows 声道模式，之后才开始采集。

每只已分配且未静音的音箱初测三次，取中位数，以最慢音箱为基准自动计算 0～500 ms 补偿；临时应用补偿后，每只再复测三次。弹窗并排显示全部初测/复测值、中位数、平均值、极差、补偿和验证结果。所有三次结果必须有效，单只音箱极差不超过 10 ms、均值与中位数差不超过 5 ms；所有音箱复测均值和中位数的最大差均须不超过 5 ms，才自动保存补偿。成功后提示是否关闭结果窗口，选择“否”可继续查看对比；也可点击“关闭”。

初测临时使用零延迟，复测通过完整路由链路，包括实际延迟缓冲。取消、噪声/削波、掉帧、时间戳异常、不稳定或未对齐时，不保存新补偿。原有补偿不变，恢复之前的路由运行/停止状态。测量期间修改配置会终止本次测量；服务重启不重播旧测量请求。至少需要两个独立音源声道，不能用重复映射的同一声道测量多个音箱。

每只音箱共六次短扫频，一次约 2.6 秒加分析时间。LFE 使用低频扫频。麦克风和虚拟音源回环使用共同 QPC 时间基准并做相关检测；结果包含麦克风链路及声传播延迟，主要用于相对对齐，不代表经过校准的绝对电气延迟。独立 USB 设备可能存在变化，验证不通过时请先检查环境和设备，再重测。可在 Windows 中关闭麦克风降噪/回声消除等增强，避免测试声被抑制。

仅点击开始后采集，录音只保留在内存，不写音频文件。最近一次结果保存在 `%ProgramData%\ChannelBridge\calibration-result.json`。若 Windows 隐私设置或设备权限阻止服务读取麦克风，弹窗会报告失败，不会生成虚假补偿。软件算法、异常检测及界面已用合成信号验证；按用户要求，本次尚未进行麦克风实机声学验证。
## 后台运行与文件

服务 `ChannelBridge.Audio` 安装在 `%ProgramFiles%\ChannelBridge`，使用 LocalService，普通自动启动，依赖 Windows Audio/AudioEndpointBuilder。意外退出后自动恢复。关闭 UI 不停止播放；重启服务或电脑后读取保存的运行意图。设备离线时保留原设备 ID 并重试，不擅自切换设备。

“停止路由”会保存停止意图；“重启服务”不改变播放意图。配置编辑后须应用才能持久保存。“保存配置…”用于导出，“载入配置…”只导入草稿；旧版 JSON 可导入。

配置位于 `%ProgramData%\ChannelBridge\config.json`，原子替换并保留 `.bak`。状态位于 `status.json`。目录授权给安装用户、LocalService、管理员与 SYSTEM。每次启动/应用前检查服务版本，需要升级时通过 UAC 提权。Windows 模式设置也在用户授权的管理员辅助进程内执行。

管理员 PowerShell 卸载服务：

```powershell
sc.exe stop ChannelBridge.Audio
sc.exe delete ChannelBridge.Audio
```

## 验证与构建

已通过 13×13 源/目标布局自动匹配、音量/静音、顺序测试、重启恢复、216 DPI UI 检查。在当前 CABLE Input 上验证 Windows 声道数、位置掩码及扬声器属性同步，并恢复原格式。详见 `验证结果.txt`。没有对所有实体扬声器配置逐一做声学测量。

使用 C#、Windows Forms、NAudio 2.2.1、.NET 10。自动设置格式使用 Windows 的非公开音频策略接口，并经读回校验；其他 Windows/驱动版本可能不支持，会显示错误，不会假报成功。源设备的 Windows 扬声器属性通过 Core Audio 属性存储提交。许可文件位于 `app/licenses`。

```powershell
dotnet publish .\ChannelBridge.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o .\app
```
